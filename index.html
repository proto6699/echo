I accidentally built a ground control station

07 SEP 2026 · 3 MIN READ
→
data-modal-text=" This started with a pretty simple question: how does a ground station actually talk to a drone?

I use things like QGroundControl, but there's a big difference between using the magic button and knowing what happens after you press the magic button.

So I started building GroundLink.

The backend is written in Rust. MAVLink handles the vehicle communication, rust-mavlink handles MAVLink messages, Axum handles the web side, and WebSockets push live telemetry into a simple HTML/CSS/JavaScript dashboard.

The fun problem was testing it. I didn't want development to require having an actual quad connected every time I changed something, so GroundLink now has a native Rust demo mode.

Running 'cargo run -- --demo' switches the application to its own simulated vehicle source. That lets me test telemetry and mission behavior without risking real hardware.

Right now it's still a prototype. The next big step is replacing Fake Drone™ with a real ArduPilot flight controller and MAVLink telemetry link.

Same software. Considerably more consequences.

The point isn't really to replace QGroundControl. I built this because I wanted to understand the chain myself:

Human → UI → Rust → MAVLink → ArduPilot → Drone → physics :( " >
